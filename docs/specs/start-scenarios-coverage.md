# Start Scenarios Coverage

Покрытие сценариев для команд /start, /session_new, /restart_session, /session_close.

Легенда:
- ✅ Работает
- ⚠️ Работает, но с проблемами
- ❓ Неизвестно / не проверено
- ❌ Не работает

---

## 1. НАЧИНАЕТ ПРОЕКТ С НУЛЯ

### 1.1 Обычный чат / Личка

**Директория не существует:**
- Спросить: создать / clone / custom path → ✅ Работает

**Директория не существует → пользователь выбрал "создать":**
- Спросить git setup (init / gh / clone / none) → ✅ Работает

**Директория не существует → пользователь выбрал "clone":**
- git clone URL → запуск Claude → ✅ Работает

**Директория существует, пустая, без git:**
- Спросить git setup? → ❓ Не уверен как работает

**Директория существует с файлами, без git:**
- Сразу запуск? Или спросить git? → ❓ Не уверен

**Директория существует с файлами, есть git:**
- Сразу запуск Claude → ✅ Работает

### 1.2 Мультигруппа — General

Всё то же что 1.1, но дополнительно:
- Должен создаваться threads[None] с name="main"
- tmux: `claude-{project}`
- **Статус:** ❓ Сейчас НЕ создаёт threads[None], идёт в legacy flow

### 1.3 Мультигруппа — Топик

- Нерелевантно — начинать проект из топика нельзя
- Проект должен быть создан через General

## СВОДКА ПРОБЛЕМ

### Критичные (ломают основной flow):

1. /start в General идёт в legacy flow, не создаёт threads[None]
2. /start в General показывает ВСЕ tmux вместо только main

### Средние (неудобства):

3. /start в pending/новом топике использует magic name вместо запроса имени
4. /session_new в топике — поведение не определено
5. /session_new в обычном чате — не проверено

### Неизвестные:

6. Tmux существует, но Claude внутри не запущен
7. Tmux с нестандартным именем в обычном чате
8. Бот рестартнулся — poller/watcher не восстанавливаются
9. Топик создан вручную + tmux по конвенции уже существует
