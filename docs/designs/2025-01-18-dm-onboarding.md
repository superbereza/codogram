# DM Onboarding + Dashboard

## Overview

Онбординг для новых пользователей при /start в директ бота + дашборд для просмотра всех подключённых проектов.

## User Storage

Для отслеживания онбординга нужно хранить состояние per-user. Расширяем `~/.codogram/config.json`:

```json
{
  "users": {
    "123456789": {
      "onboarded": true,
      "onboarded_at": "2026-01-18T12:00:00"
    }
  },
  "projects": { ... }
}
```

Каждый админ (из `ADMIN_IDS`) должен увидеть онбординг хотя бы один раз.

## Онбординг

### Триггер

Админ отправляет `/start` в DM бота И `users[user_id].onboarded != true`.

После завершения онбординга (показан CTA) — помечаем `onboarded: true`.

### Флоу

```
/start в DM
    ↓
[user.onboarded?]
    ├─ да → мини-статус (см. ниже)
    └─ нет ↓

1. Приветствие (отдельное сообщение)
    ↓
2. Карусель ценностей (редактируемое сообщение с кнопками ← →)
   - Слайд 1: Мобильность — запускай задачи с телефона, работай откуда угодно
   - Слайд 2: Асинхронность — запустил → занялся своим → получил уведомление
   - Слайд 3: Команда — настрой один раз, работай с коллегами
    ↓
3. Валидация окружения
   ├─ ❌ Проблема → "Вернись на сервер, исправь X" + мини-инструкция
   │                 Кнопка [Проверить снова]
   └─ ✅ Всё ок → далее
    ↓
4. CTA: "Создай группу, добавь меня админом. Бот подхватит автоматически"
    ↓
🏁 Онбординг завершён, user.onboarded = true
```

### /start для онборженных юзеров

Если юзер уже прошёл онбординг, `/start` в DM показывает мини-статус:

```
👋 С возвращением!

Активных проектов: 2
Сессий Claude: 3

/dash — подробный список проектов
/intro — посмотреть введение ещё раз
```

### Карусель — stateless

Состояние карусели НЕ хранится. Текущий слайд передаётся в callback data:
- `onb:slide:0`, `onb:slide:1`, `onb:slide:2`
- Кнопка "Далее" на слайде 1 → callback `onb:slide:2`

Если юзер закрыл Telegram и вернулся — покажем с начала (не критично).

### Callback patterns

Все callback data в DM:
- `onb:slide:N` — переход на слайд N карусели
- `onb:recheck` — повторная валидация окружения
- `dash:refresh` — обновить дашборд

### Повторный просмотр

Команда `/intro` — показывает онбординг заново (для тех кто хочет освежить память).

### Валидация окружения

**Критичные (блокируют):**
- `BASE_DIR` указан в конфиге (не пустой)
- `BASE_DIR` существует на диске
- `claude` доступен в PATH
- `tmux` доступен

**Варнинги (показываем, не блокируем):**
- `git config user.name/email` не настроен
- `gh auth status` не авторизован
- SSH ключи отсутствуют

### Тон

Прагматичный, без маркетингового хайпа. Референс: https://granda.org/en/2026/01/02/claude-code-on-the-go/

## Пуш при добавлении в чат

Когда бота добавляют в любой чат (независимо от онбординга), отправляем уведомление в DM **всем админам** (из `ADMIN_IDS`):

```
Меня добавили в «Chat Name»
Создатель: @username
```

Ссылка на чат: используем `chat.invite_link` если доступен, иначе не показываем (приватные группы без публичной ссылки).

## Дашборд

### Команда
`/dash` — доступна только в DM, только для админов.

### Формат

```
📊 Проекты

1. codogram
   📁 /home/user/dev/codogram
   👤 Создатель: @superbereza
   👥 3 участника
   🤖 2 сессии Claude

2. my-app
   📁 /home/user/dev/my-app
   👤 Создатель: @teammate
   👥 5 участников
   💤 не активен

Всего: 2 проекта, 2 активных сессии

[Обновить]
```

### Поля
- Название чата (заголовок)
- Директория проекта (BASE_DIR/project)
- Создатель чата (@username)
- Количество участников
- Статус Claude сессий (N сессий / не активен)
- Кнопка "Обновить"

### Empty state

Когда нет подключённых проектов:

```
📊 Проекты

Пока нет подключённых проектов.

Создай группу и добавь меня — я подхвачу автоматически.

[Обновить]
```

## DM режимы

1. **Онбординг** — для новых пользователей, показывается один раз
2. **Дашборд** — для опытных, вызывается через `/dash`
3. **Уведомления** — пуши о добавлении в чаты

DM отвечает только админам (ADMIN_IDS из .env).
